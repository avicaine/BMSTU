# Лабораторная работа № 2 — ввод-вывод в файлы (Си++)

**Вариант 8.** Структура «товар в магазине (на складе)»: название, число единиц в наличии, стоимость одной единицы.

Программа хранит вектор товаров, умеет сохранять его в файл и читать обратно в **текстовом** и **двоичном** режимах. Режим задаётся параметрами командной строки.

```
lab2 <write|read> <text|binary> <имя_файла>
```

| Команда | Что делает |
|---|---|
| `lab2 write text goods.txt` | вводит товары с клавиатуры → пишет в текстовый файл |
| `lab2 write binary goods.dat` | вводит товары с клавиатуры → пишет в двоичный файл |
| `lab2 read text goods.txt` | читает текстовый файл → печатает на консоль |
| `lab2 read binary goods.dat` | читает двоичный файл → печатает на консоль |

## Содержимое репозитория

```
main.cpp                      исходный код (все функции с комментариями)
examples/input.txt            готовый ввод для проверки (4 товара)
examples/goods.txt            результат записи в текстовом режиме
examples/goods.dat            результат записи в двоичном режиме
examples/session_*.txt        консольные сессии записи
examples/output_read_*.txt    вывод при чтении
```

## Сборка и запуск

```bash
g++ -std=c++17 -Wall -Wextra -o lab2 main.cpp

# запись (ввод руками или из готового файла)
./lab2 write text   goods.txt < examples/input.txt
./lab2 write binary goods.dat < examples/input.txt

# чтение
./lab2 read text   goods.txt
./lab2 read binary goods.dat
```

В Visual Studio параметры командной строки задаются в *Свойства проекта → Отладка → Аргументы команды*.

Коды возврата: `0` — успех, `1` — файл не открылся, `2` — неверный ввод, `3` — файл неверного формата, `5` — неверные параметры командной строки.

## Пример работы

Запись (`lab2 write text goods.txt`), введённые данные видны после приглашений:

```
n=4
Product N=1
Name: Laptop Lenovo IdeaPad 3
Count: 12
Price: 54999.90
...
```

Чтение (одинаковый результат и для text, и для binary):

```
1. Laptop Lenovo IdeaPad 3, in stock: 12 pcs, price: 54999.90
2. Wireless mouse Logitech M185, in stock: 150 pcs, price: 799.50
3. Monitor Samsung 24 inch, in stock: 35 pcs, price: 12490.00
4. Mechanical keyboard Redragon, in stock: 48 pcs, price: 3250.00
```

## Как это сделано

1. **Структура** `PRODUCT` с тремя полями: `string Name`, `int Count`, `double Price`. Строка `string` вместо `char[]` — чтобы не думать о длине названия.
2. **Вектор** `vector<PRODUCT> Goods` хранит `n` товаров; размер задаётся через `resize(n)` после ввода `n`.
3. **Одна пара функций на оба режима.** `write_product` и `read_product` принимают флаг `binary` и внутри делают `if/else`. Так формат файла описан в одном месте, а запись и чтение легко сверить зеркально.
4. **Файл начинается с числа `n`** — так при чтении известно, сколько товаров ждать.
5. **Текстовый формат.** Название — отдельной строкой (в нём могут быть пробелы, поэтому читается `getline`), число и цена — в следующей строке через пробел:
   ```
   4
   Laptop Lenovo IdeaPad 3
   12 54999.90
   ...
   ```
6. **Двоичный формат.** Данные пишутся «как в памяти» через `write` / `read`. Строка записывается вместе с нулевым байтом `'\0'` — он служит признаком конца, а при чтении `getline(in, s, '\0')` останавливается на нём.
7. **Подводные камни**, которые обработаны:
   - после `cin >> n` в потоке остаётся `'\n'`, поэтому перед `getline` стоит `cin.ignore(...)`, иначе первое название прочиталось бы пустым;
   - для двоичного файла обязателен флаг `ios::binary`, иначе в Windows `'\n'` превратился бы в `'\r' '\n'` и данные испортились бы;
   - при чтении текстового файла, созданного в Windows, убирается лишний `'\r'` в конце названия;
   - проверяются параметры командной строки, открытие файла и формат прочитанных данных.

### Как выглядит двоичный файл

```
04 00 00 00                  n = 4 (int, 4 байта, порядок little-endian)
4c 61 70 74 6f 70 ... 33 00  "Laptop Lenovo IdeaPad 3" + нулевой байт
0c 00 00 00                  Count = 12 (int)
cd cc cc cc fc da ea 40      Price = 54999.90 (double, 8 байт)
... дальше те же три блока для остальных товаров
```

## Сравнение размеров файлов

| Файл | Размер |
|---|---|
| `goods.txt` (текстовый) | 154 байта |
| `goods.dat` (двоичный) | 158 байт |

Названия занимают одинаково в обоих файлах (в тексте их завершает `'\n'`, в двоичном — `'\0'`, по одному байту). Разница только в числах:

- в двоичном файле каждое число занимает фиксированное место: `int` — 4 байта, `double` — 8 байт, итого 12 байт на товар и 4 байта на `n`;
- в текстовом файле число занимает столько символов, сколько в нём цифр. Здесь числа короткие (`12`, `150`, `799.50`), поэтому текст вышел чуть меньше.

Если числа длинные (например, `1000000` и `1234567.89`), текстовый файл станет больше двоичного. Кроме того, в Windows каждый `'\n'` в текстовом файле записывается как два байта `'\r' '\n'`, и тот же файл будет на 9 байт длиннее (9 строк). Размеры в таблице получены в Linux, в Windows у тебя текстовый файл будет 163 байта.

Ещё одно отличие: двоичный файл зависит от платформы (размер `int`, порядок байтов), а текстовый можно открыть где угодно.

## Вопросы для самоконтроля

1. **Режимы открытия файлов:** `ios::in` (чтение), `ios::out` (запись), `ios::ate` (после открытия встать в конец файла), `ios::app` (дописывать в конец), `ios::binary` (двоичный режим), в учебнике ещё `ios::nocreate` (не создавать новый файл) и `ios::noreplace` (не открывать существующий); в стандарте Си++ есть также `ios::trunc` (очистить файл при открытии).
2. **Текстовый и двоичный режимы:** в текстовом режиме при записи `'\n'` превращается в `'\r' '\n'` (в Windows), а при чтении обратно; числа хранятся как цепочки символов-цифр, файл можно прочитать глазами. В двоичном режиме байты пишутся и читаются без преобразований, числа хранятся в машинном виде фиксированного размера.
3. **Файл обязан существовать:** `ios::in` и `ios::nocreate`.
4. **Файл создаётся заново (старое содержимое стирается):** `ios::out` (когда он указан один, без `ate` и `app`) и `ios::trunc`.
